# 0019 上下文压力：提前压缩、摘要请求收缩与工具输出上限

- 状态：已接受（修订 [0008](0008-agent-loop-and-sessions.md) 中 compaction 的触发时机）
- 日期：2026-11-12

## 背景

[0008](0008-agent-loop-and-sessions.md) 规定了运行中两种触发压缩的情况：模型报 `context-length` 且没有任何输出，或者设置了 `compactAboveTokens` 并超过阈值。实际使用中有三处漏洞，连起来就会让会话卡住：

1. **从不提前压缩**。Host 挂载 `AgentLoop` 时没有传 `compactAboveTokens`，只能等 provider 报错。有些本地模型服务（例如 Ollama）超长时并不报错，而是静默截断上下文，连这次被动压缩都触发不了。
2. **摘要请求本身也可能超长**。按 0008，运行中的压缩会把整个分支原样发给同一个模型去总结，这个请求和刚刚失败的那个差不多大。
3. **工具输出没有统一上限**。`read`、`bash` 会自己截断，MCP、浏览器、子 agent 的输出则原样进入上下文。一次大的返回就能直接撑满上下文。

## 决策

### 1. 按上下文窗口提前压缩

- 没有设置 `compactAboveTokens` 时，`AgentLoop` 从 provider 的模型列表里读取当前模型的 `contextWindow`。上一次调用用掉的 token（输入、缓存、输出合计）超过窗口的 `compactAtContextRatio`（默认 0.8）时，在下一次调用前压缩。
  - 窗口未知的模型不提前压缩，行为和以前一样。
  - 窗口按模型缓存 10 分钟；查询最多等 5 秒，超时就按未知处理，不能拖住这一轮。
  - `compactAtContextRatio: 0` 关闭这项功能；设置了 `compactAboveTokens` 时以它为准。
- Anthropic 适配器的模型发现补充读取 Models API 的 `max_input_tokens` 和 `max_tokens`，分别作为 `contextWindow` 和 `maxOutputTokens`。其他适配器原本就会读取窗口信息。
- **第一轮之前压缩时保留新消息原文**：一次运行开始、还没调用模型时，最新一轮只有用户刚发的消息，没有工具结果，所以只总结它之前的内容。运行中第二轮及以后的压缩仍按 0008，总结整个分支。

### 2. 摘要请求逐级收缩

- 先用原样的历史请求摘要。如果模型报 `context-length`，就逐级收缩后重试（`SUMMARY_CLIP_LEVELS`：先 8000 字符，再 1000 字符）。
  - 收缩时，用户消息、工具结果和工具调用参数里的长文本只保留开头和结尾，图片换成 `[image omitted]`。
  - 模型自己的文字和 thinking 不动。
- 只有报 `context-length` 才进入下一级，其他错误仍按原逻辑处理。

### 3. 工具输出上限（`@qianji/tool-output`）

- 新的内置插件挂在 `tools/execute` 上，[0003](0003-plugin-model-and-events.md) 把这个扩展点留给了输出截断。
- 文本超过 50000 字符时，保留开头和结尾各 40%，全文存到 `<dataDir>/spill/<sessionId>/<callId>.txt`，并在结果里告诉模型路径，以及可以用 `read` 翻页、用 `grep` 搜索。
- 会话日志里保存的是截断后的结果，日志不会被一次大输出撑大。
- spill 目录在 Host 启动时清理，超过 7 天的会话目录会被删除。

## 后果

- 窗口已知的模型在接近上限前就会压缩，不必等 provider 报错。本地模型只要在 `providers.json` 里写明 `contextWindow`，也能受到保护。
- 一次大输出不再能单独撑满上下文。压缩即使在超长之后才触发，摘要请求也能逐级缩小到可以发出去。
- 超长输出的中间部分模型看不到，需要时得自己去读 spill 文件。
- 会话被删除后，它的 spill 文件要等保留期到了才会被清理。

## 备选方案

- **固定的 token 阈值**：上下文窗口从 32k 到 1M 不等，没有一个通用的数字。否决。
- **超长时直接丢掉最早的消息**：会丢失任务目标等关键信息，摘要能保住它们。否决。
- **把输出上限写进各个工具**：每个 MCP 服务器和插件都要各写一遍。放在 `tools/execute` 上一处就能统一覆盖。否决。

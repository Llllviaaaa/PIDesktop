# Pi Desktop 0.3.0 发布说明

0.3.0 是 V2 重构的第一个正式版本：桌面端不再内置 Pi，任务改由自建的 Harness Host 运行（`docs/REFACTOR_V2*.md`）。界面、名称和数据所在的位置大体不变，但模型提供商、密钥、技能和历史任务的存放位置变了。本文说明从 0.2.x 升级时会发生什么、需要你做什么，以及发布前要在安装包上逐项确认的检查清单。

## 从 0.2.x 升级

### 数据位置

Harness 的数据都在 `~/.pid` 下：

| 内容 | 位置 |
|---|---|
| 会话 | `~/.pid/sessions/*.jsonl` |
| 模型提供商 | `~/.pid/providers.json` |
| 密钥 | `~/.pid/secrets.dat`（DPAPI 加密，只有本机当前用户能解密） |
| 定时任务 | `~/.pid/schedules.json` |
| Harness 配置 | `~/.pid/harness.json`（由桌面端设置生成） |
| 日志 | `~/.pid/logs/host-*.log`、`desktop-*.log`，保留 7 天 |

桌面端自己的设置仍在 `%APPDATA%/pid-desktop/settings.json`。Pi 的目录（`~/.pi/agent`）只会被读取，不会被修改或删除。

### 首次启动时自动迁移的内容

- **模型提供商和密钥**：
  - Pi `models.json` 里的自定义提供商会写入 `providers.json`。
  - Pi `auth.json` 里用 **API 密钥**登录的内置提供商会连同密钥一起迁移，密钥存进 `secrets.dat`。
  - 只迁移一次；之后两边各自维护。
- **技能、主题和宠物**：
  - `~/.pi/agent` 下的技能、主题和宠物会复制到 `.pid/`，已存在的不会被覆盖。
  - 项目里 `.pi/` 下的资源不会自动复制。设置里会提示还有多少没复制，点“复制到 .pid/”即可。
- **定时任务**：桌面端原有的定时任务会迁移到 Host，由 Host 在应用运行期间执行。

### 需要你确认的内容

- **历史任务**：
  - 第一次启动时会询问是否把 Pi 的历史任务导入 Harness。
  - 导入只读取 Pi 的会话文件，原文件不变。
  - 选择“以后再说”也没关系，随时可以在 设置 › 已归档 › 导入到 Harness 里导入。
- **OAuth 登录不再支持**：
  - 在 Pi 里用订阅账号登录的提供商（例如 Claude Pro/Max、ChatGPT Plus/Pro）不会迁移，启动时会在日志里说明。
  - 请在 设置 › 模型与连接 里为这些提供商填写 API 密钥。也可以在提供商配置里填写 `$环境变量`，由 Harness 在使用时读取。
- **独立的 Pi 配置、Pi 扩展和 packages**：这些只对 Pi 有效，0.3.0 不再加载。

### 其他变化

- **崩溃恢复**：
  - Harness 异常退出后会自动重启并重新连接，界面顶部会显示“Harness 已断开，正在重连”。
  - 断开时正在进行的一轮会标记为中断，不会自动重试。
  - 一分钟内连续崩溃 5 次后不再自动重启，顶部会提供“重新启动”按钮。
- **诊断**：设置 › 调试 里可以打开日志目录，或导出诊断包。诊断包是一个 zip，包含最近的日志、版本号和 `harness.json`，密钥已脱敏，可以附在问题报告里。
- **安装包**：不再包含 `pi.exe` 和 Pi 运行时，改为包含 `harness/pid-harness.exe`。

## 发布前的手动检查清单

以下项目在 P5–P7 的 PR 里标记为“未在应用中验证”，自动测试覆盖不到真实的 Tauri 窗口和安装过程，发布前需要在安装包上逐项确认。

**安装与迁移**（#98、#93、#94、#96、#97）

- [ ] 全新安装：启动后直接使用 Harness，可以配置提供商并完成一个任务。
- [ ] 覆盖安装 0.2.29：
  - [ ] Pi 的提供商和 API 密钥都在。
  - [ ] OAuth 提供商在日志里有说明。
  - [ ] 技能出现在技能列表里。
  - [ ] 主题和宠物可以选择。
- [ ] 覆盖安装 0.2.29：首次启动询问导入历史任务；导入后任务出现在侧边栏，可以打开。
- [ ] 安装目录里没有 `pi.exe`；有 `harness/pid-harness.exe`。

**任务与会话**（#87、#88、#89、#99、#100）

- [ ] 发送消息，看到流式的文字和思考过程；工具调用显示结果。
- [ ] 中途追加指令（steer）、中止、切换模型和推理等级。
- [ ] 权限确认：允许和拒绝各一次。
- [ ] 回退消息、编辑后重新发送。
- [ ] 从最新检查点分叉。
- [ ] 会话树：应用里目前没有会话树视图，确认这是否符合预期。
- [ ] 新任务出现在侧边栏，可以重新打开、归档、恢复、导出 Markdown、删除。
- [ ] 侧边聊天（#92）：在新任务发出第一条消息后打开右侧栏（Ctrl+Alt+B），开始侧边聊天并得到回复。E2E 套件已覆盖；之前新任务的会话文件只在重新打开后才记录，右侧栏因此打不开。

**设置与其他页面**（#90、#91、#96、#105）

- [ ] 模型与连接：
  - [ ] 添加自定义提供商。
  - [ ] 为提供商填写、更换、删除 API 密钥。
  - [ ] “检查连接”。
- [ ] 定时任务：新建、立即运行、打开运行产生的会话；用量页面有数据。
- [ ] 提交对话框：生成提交信息。
- [ ] 设置 › 调试：
  - [ ] “打开日志目录”打开 `~/.pid/logs`。
  - [ ] “导出诊断包”生成的 zip 能用资源管理器打开。
  - [ ] `desktop-*.log` 有内容。

**崩溃恢复**（#103）

- [ ] 在任务管理器里结束 `pid-harness.exe`：
  - [ ] 顶部出现“Harness 已断开，正在重连”，随后消失。
  - [ ] 进行中的一轮显示为中断。
  - [ ] 之后可以继续发送消息。
- [ ] 一分钟内连续结束 5 次：
  - [ ] 顶部出现“Harness 多次崩溃”。
  - [ ] “重新启动”按钮能恢复。
